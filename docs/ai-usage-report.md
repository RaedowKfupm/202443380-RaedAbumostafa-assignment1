# AI Usage Report

## Purpose

AI assistance was used as a development aid while building and refining this portfolio. The final implementation was reviewed in the workspace, adapted to the project requirements, and tested locally by the developer.

## Tools Used

- GitHub Copilot in VS Code for code suggestions, debugging support, documentation drafting, and implementation guidance.
- Browser preview and a local static server for visual verification.
- Git for tracking the developer's own changes and maintaining project history.

## How AI Assisted

AI assistance was used to:

- Scaffold the HTML, CSS, JavaScript, asset, and documentation structure.
- Suggest semantic HTML, responsive CSS, accessible form markup, and vanilla JavaScript interactions.
- Help diagnose image-cropping and contact-section overflow issues.
- Draft the README, technical documentation, and this usage report from the implemented behavior.
- Review wording and improve responsive presentation of the contact headline.

## Developer Review and Modification

AI-generated suggestions were treated as starting points rather than final answers. The developer selected the portfolio content, supplied and organized the personal images, corrected wording, reviewed the visual result in the browser, and requested targeted layout changes. Code was kept dependency-free and limited to the assignment requirements.

The developer also checked that the contact form clearly states that it is a demo and does not transmit or store submitted data. This avoids implying that the static page provides a real communication channel.

## Benefits

AI reduced the time needed to establish a coherent page structure and provided useful alternatives for responsive layout, accessibility attributes, and validation logic. It was especially helpful for identifying the relationship between text width, responsive font sizing, and overflow in the contact section.

## Challenges and Limitations

AI suggestions can make assumptions about the intended visual design, content, or browser behavior. Some suggestions required manual correction after visual inspection, particularly image framing and long headline wrapping. AI cannot replace checking the rendered page, testing keyboard interaction, or confirming that content accurately represents the developer's work.

## Learning Outcomes

This workflow reinforced the importance of:

- Using semantic HTML before adding visual styling.
- Testing responsive behavior at actual viewport sizes instead of relying only on source code.
- Treating accessibility states such as `aria-expanded`, `aria-current`, and `aria-invalid` as part of the feature behavior.
- Keeping static-site scope clear when a form has no backend.
- Reviewing and understanding every generated change before accepting it.

## Responsible Use Statement

The developer remains responsible for the final code, content, asset rights, testing, and documentation. AI assistance did not replace authorship or verification; it supported implementation and learning while the developer made the final decisions.
